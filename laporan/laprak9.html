ATujuan Praktikum

Praktikum ini bertujuan menggabungkan hasil Praktikum 1 sampai 5 (widget, layout, form, navigasi, named routes dan bottom navigation) menjadi satu project aplikasi Expense Tracker. Setelah praktikum, mahasiswa mampu: (1) menyimpan data secara permanen dengan SQLite (sqflite) sehingga data tidak hilang saat aplikasi ditutup; (2) membuat fitur register dan login dengan data pengguna di penyimpanan lokal; (3) membuat video penjelasan aplikasi; dan (4) menghasilkan file APK.

Desain UI/UX praktikum dipertahankan, kecuali halaman login dan register yang merupakan halaman baru.

BDasar Teori

SQLite adalah database relasional ringan yang tersimpan sebagai satu file di perangkat. Pada Flutter, package sqflite dipakai untuk membuat tabel dan menjalankan query (insert, query, delete). Karena akses database memakan waktu, semua operasinya bersifat asinkron (Future, async, await).

SharedPreferences menyimpan data kecil berpasangan kunci-nilai; di sini dipakai untuk sesi login (id pengguna yang sedang masuk). Hash SHA-256 mengubah password menjadi deretan karakter satu arah, sehingga password asli tidak disimpan di database.

Konsep dari praktikum sebelumnya yang tetap dipakai: StatelessWidget/StatefulWidget dan setState (P1), Row/Column/ListTile (P2), Form/validator/showDatePicker (P3), Navigator.push/pop dan passing data lewat constructor (P4), serta named routes dan BottomNavigationBar (P5).

CAlat dan Bahan
  • Flutter SDK, Dart, Visual Studio Code, dan Android Studio (Android SDK, NDK)
  • Emulator Pixel 6 dan HP Android (untuk uji APK)
  • Package: sqflite, path, shared_preferences, crypto, cupertino_icons
  • Database Inspector (Android Studio) untuk melihat isi tabel
DLangkah Praktikum

Bagian ini menjelaskan urutan pengerjaan dari awal sampai akhir. Ikuti urutan nomor berikut; setiap nomor mengarah ke langkah rinci beserta tangkapan layar dan penjelasan kodenya.

  1. Persiapan lingkungan dan membuat project (Flutter, Android Studio, SDK, folder lib)
  2. Menambahkan dependency di pubspec.yaml
  3. Membuat model data (AppUser, TransactionModel)
  4. Membuat database SQLite (database_helper.dart) karena dipakai semua halaman
  5. Membuat sesi login dan hash password (session.dart, helpers.dart)
  6. Mendaftarkan named routes di main.dart dan membuat splash
  7. Membuat halaman Register dan Login
  8. Membuat MainScreen dengan Bottom Navigation Bar
  9. Membuat Dashboard (saldo, ikon mata, daftar transaksi)
  10. Membuat form Tambah Transaksi (validasi, dropdown, tanggal)
  11. Membuat Riwayat dan Detail Transaksi
  12. Membuat halaman Profil dan Logout
  13. Menjalankan dan menguji seluruh fitur, termasuk isi database
  14. Merekam video penjelasan
  15. Membangun APK dan memasangnya di HP

Catatan urutan: file database_helper.dart dan session.dart dibuat lebih dulu (langkah 4 dan 5) karena dipanggil oleh dashboard, form, riwayat, login, dan profil. Dua bagian itu tertulis pada bagian Latihan (E) karena merupakan tambahan dari ketentuan tugas akhir.

Pembahasan. Penggabungan praktikum 1–5 berhasil: navigasi memakai named routes, tampilan memakai widget dan layout praktikum, input memakai form tervalidasi, dan data berasal dari SQLite. Perbedaan utama dari praktikum sebelumnya adalah data tersimpan permanen dan setiap akun punya data sendiri. Keterbatasan: password di-hash tanpa salt, dan tombol Transfer bawaan desain praktikum tidak dikembangkan.

GKesimpulan

Kesimpulan praktikum ini:

  1. Praktikum 1–5 berhasil digabung menjadi satu project Expense Tracker dengan desain UI/UX tetap dipertahankan.
  2. SQLite (sqflite) membuat data tidak hilang walau aplikasi ditutup.
  3. Register dan login berfungsi, dengan password ter-hash SHA-256 dan sesi di SharedPreferences.
  4. Data setiap akun terpisah melalui kolom user_id.
  5. Aplikasi berhasil dibuild menjadi APK dan berjalan di HP Android.
